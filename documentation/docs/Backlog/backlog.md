# Estrutura do Backlog

Foi decidido em grupo que o Backlog teria a seguinte hierarquia:

- **Épico** → **Feature** → **User Story (US)** → **Tasks**

### Critérios de Escrita

As User Stories e Tasks são escritas de forma clara e granular, utilizando uma linguagem acessível para que todos os membros da equipe consigam entender e contribuir.

### Hierarquia de Itens:

- **Épicos**: Representam as fases clássicas do desenvolvimento de um compilador (Léxico, Sintático, Semântico, etc.).
- **Features**: Componentes funcionais grandes, como "Scanner Flex" ou "Parser Bison".
- **User Stories**: Requisitos funcionais e técnicos mais específicos que descrevem objetivos do usuário ou da funcionalidade.
- **Tasks**: Passos atômicos que devem ser seguidos para realizar cada User Story, geralmente implementáveis em poucas horas ou um único commit.

### Padrões Adotados:

- Cada User Story possui 2 a 5 Tasks associadas.
- Todas as US possuem status: "Feito", "Em andamento" ou "A Fazer".
- Sempre que possível, cada Task está ligada a um critério de aceitação ou teste automatizado.

Essa organização permite uma gestão eficiente e clara, alinhada aos princípios ágeis da metodologia Scrum.
