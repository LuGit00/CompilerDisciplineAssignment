    Estrutura do Backlog

    Foi decidido em grupo que o Backlog terá a seguinte estrutura: Épico → Feature → User Story → Tasks, sendo que os Épicos representam cada fase de um Compilador, e que vão se decompondo em subtarefas (Feature, US's e Task). As User Stories e as Tasks são escritas de forma granular e com linguagem acessível para que todos do time sejam capazes de entender cada tarefa e realizá-las com eficiência.

    Épicos

    Épico A - Análise Léxica

    Feature A.1: Implementador do Scanner (Flex) — Status: Feito.

    • US-01: Reconhecer palavras-chave (if, else, while, for, return, struct, typedef, etc.) — Statu - Tasks:
    • Listar palavras-chave alvo e inserir em arquivo de tokens.
    • Escrever regras Flex para cada palavra-chave.

    • Adicionar teste unitário que valida reconhecimento de cada palavra-chave.

    • US-02: Reconhecer identificadores, literais numéricos e caracteres — Status: Feito.

    • Tasks:
    • Implementar expressão regular para identificadores (letra + alfanum/_).
    • Implementar regex para literais (inteiros decimais, hex se necessário).

    • Criar testes unitários cobrindo casos válidos/inválidos.

    • US-03: Detectar e reportar erros léxicos — Status: Feito (básico).

    • Tasks:
    • Implementar token <INVALID> que captura símbolos inválidos.
    • Produzir mensagem de erro com linha/coluna.

    • Adicionar teste que assegura erro léxico esperado em input malformado.

    • US-04: Testes automatizados do léxico — Status: Feito (framework presente).

    • Tasks:
    • Integrar testes de léxico no pipeline de testes.
    • Cobrir tokens críticos com casos positivos/negativos.
    • Criar fixture para carregar pequenos arquivos-sample.

    Épico B — Análise Sintática

    Feature B.1: Gramática de Estruturas de Controle (Bison) — Status: Parcial/Feito (básico).

    • US-05: Suporte a if / else — Status: Feito.
    • Tasks:
    • Adicionar regras Bison para if/else com produção única e com elif suportado via else-ifencadeado.

    • Testar casos com aninhamento e ausência de else.

    • US-06: Suporte a loops (while, for) — Status: A Fazer.

    • Tasks:
    • Escrever gramática para while (condição e bloco).
    • Escrever gramática para for (inicialização; condição; passo; bloco).

    • Testes que verifiquem saltos e escopos internos.

    • US-07: Suporte a goto / label — Status: Feito.

    • Tasks:
    • Mapear token LABEL e GOTO na gramática.
    • Criar pass semântica que resolve labels (flag de resolução tardia).

    • Testes de jump intra-função inválos (ex.: goto para label fora da função -> erro).

    • US-08: Funções (declaração e corpo) — Status: Em Andamento / A Fazer.

    • Tasks:
    • Definir produção para function_definition (tipo retorn, id, params, body).
    • Implementar parsing de lista de parâmetros (possibilidade vazia).

    • Testes de definição e chamadas simples.

    • US-09: Construção da AST — Status: Feito (parcial).

    • Tasks:
    • Definir estrutura de nós AST (Node type, children, token info).
    • Alterar ações Bison para criar nós AST em vez de prints temporários.

    • Serializar AST em formato textual para debug (ex.: S-expr).

    • US-10: Testes do parser / mensagens de erro sintático — Status: Feito/Em Andamento.

    • Tasks:
    • Implementar harness de teste para rodar parser em inputs e comparar AST.
    • Melhorar mensagens de erro com sugestão de recuperação (panic mode simples).
    • Cobrir casos sintáticos inválidos no suite.

    Épico C — Análise Semântica

    Feature C.1: Tabela de Símbolos e Escopagem — Status: Em Andamento.

    • US-11: Implementar tabela de símbolos (escopos: global, função, estrutura).
    • Tasks:
    • Criar structs C para Symbol e SymbolTable com encadeamento de escopos.
    • Implementar enter_scope() / exit_scope() nas ações semânticas do parser.

    • Testes de lookup que confirmem visibilidade e sombra (shadowing).

    • US-12: Resolução de labels por escopo — Status: A Fazer.

    • Tasks:
    • Registrar labels na tabela de symbols com info de função.
    • Ao final da função, verificar labels referenciados mas não definidos → erro.

    • Testes que provoquem erro de label externo.

    • US-13: Verificação de tipos (compatibilidade) — Status: A Fazer.

    • Tasks:
    • Definir representação de tipos básicos (void, int, char, pointer).
    • Implementar verificação em atribuições e retorno de função.

    • Criar mensagens de erro com local e causa.

    • US-14: Suporte a variáveis (estática, automática, registrador, imediata) — Status: Em Andament - Tasks (por tipo):

    • Estático:
    • Implementar armazenamento simbólico e geração de label global.
    • Teste: variável estática inicializada.
    • Automática (stack):
    • Definir layout de stack-frame (offset por variável).
    • Código de alocação/desalocação no prólogo/epílogo de função.
    • Teste: funções recursivas simples com variáveis locais.
    • Registrador:
    • Marcar variáveis elegíveis para alocação em registrador (heurística simples).
    • Tests: atribuição e leitura em registrador vs stack.
    • Imediata:

    • Suportar constantes inline em expressões e propagação simples.

    • US-15: Ponteiros e endereçamento (&, *) — Status: A Fazer.

    • Tasks:
    • Adicionar tipos ponteiro na representação de tipos.
    • Implementar semântica de & para variáveis l-values.
    • Tests para leitura/escrita via ponteiro.

    Feature C.2: Verificação de chamadas de função (arg count / types) — Status: A Fazer.

    • US-16: Checar número e tipos de argumentos — Status: A Fazer.
    • Tasks:
    • Registrar assinatura de função na tabela de símbolos.
    • Ao encontrar chamada, comparar tipos e número → emitir warning/erro.
    • Tests: chamada com menos/mais argumentos e tipos incompatíveis.

    Épico D — Geração de Código Intermediário (IR)

    Feature D.1: Definição e Estrutura do IR — Status: A Fazer.

    • US-17: Escolher representação (three-address code) — Status: A Fazer.
    • Tasks:
    • Especificar formato textual para IR (op, dst, src1, src2).
    • Implementar estruturas C para instruções IR.

    • Criar utilitário emit_ir(op, dst, src1, src2).

    • US-18: Gerar IR para expressões aritméticas — Status: A Fazer.

    • Tasks:
    • Implementar visitor que percorre AST de expressão e emite IR.

    • Tests: expressão com parênteses e precedência.

    • US-19: Gerar IR para controle de fluxo — Status: A Fazer.

    • Tasks:
    • Emissão de labels IR (L1, L2...) e saltos condicionais.
    • Mapear if/else e while para sequência de labels e jumps.

    • Tests end-to-end que compilam trecho e chequem IR esperado.

    • US-20: IR para funções (prólogo/epílogo) — Status: A Fazer.

    • Tasks:
    • Definir convenção de chamada simples (salvar rbp, ajustar rsp etc.)
    • Gerar IR para passagem de parâmetros (por stack/registros simples).
    • Testes com chamadas aninhadas.

    Épico E — Otimização (Opcional)

    Feature E.1: Otimizações Locais — Status: A Fazer.

    • US-21: Constant folding — Status: A Fazer.
    • Tasks:

    • Implementar passe que detecta operações com operandos constantes e substitui por constante co 2. Tests: (2+3)*4 => 20 no IR.

    • US-22: Dead code elimination (local) — Status: A Fazer.

    • Tasks:
    • Detectar instruções sem uso (def sem uso) e remover.
    • Tests que assegurem semântica preservada.

    Épico F — Geração de Código Final (Assembly x86)

    Feature F.1: Gerador Assembly x86 (texto) — Status: Em Andamento (parcial).

    • US-23: Gerar assembly para expressões aritméticas — Status: Em Andamento.
    • Tasks:
    • Mapear IR aritmético para instruções x86 (add, sub, imul, idiv).
    • Implementar gerador simples de alocação temporária (stack spill quando necessário).

    • Tests: compilar expressão e montar com as/ld (manual check).

    • US-24: Gerar assembly para controle de fluxo (if/else, loops) — Status: A Fazer.

    • Tasks:
    • Gerar labels e jumps cond/unc.
    • Assegurar que labels IR → labels ASM 1:1.

    • Tests: trecho com if-else e loop.

    • US-25: Prólogo/Epílogo de função — Status: A Fazer.

    • Tasks:
    • Emitir padrão de função (push rbp; mov rbp, rsp; sub rsp, N).
    • Restaurar registros no epílogo e ret.

    • Tests com função que retorna valor int.

    • US-26: Gerenciar registradores vs pilha — Status: A Fazer.

    • Tasks:
    • Implementar alocador de registros linear-scan simples (heurística).
    • Spill para stack quando necessário.

    • Tests com uso de muitos temporários.

    • US-27: Supporte a inserção de assembly inline — Status: A Fazer.

    • Tasks:
    • Permitir token INLINE_ASM incorporado na AST e copiado para output.
    • Validar contexto (apenas dentro de funções).
    • Testes unitários que preservem bloco inline.
